# Phase 5 Spec: Strategy Lab

Author: Claude. For: Codex. Covers T-050 to T-054. Depends on Phases 1, 2 and 4. Read `ARCHITECTURE.md` section 6, `config/strategy_lab.yaml` (gates, read-only to agents) and decisions D-019 and D-022.

## Principles
- **Plain code decides promotion.** Gates, the validator, the allocator and the decay monitor contain no LLM calls.
- **Strategies are declarative specs**, never executable code. LLM output is parsed into a `StrategySpec` or rejected. Nothing generated by an LLM is `eval`'d, imported, or run as code.
- **The sealed holdout** (the most recent `holdout_months` months) is readable only by `lab/validator.py`. Everything else, including the backtest engine used for search, receives data that ends before the holdout.
- Gate values are read from `config/strategy_lab.yaml`. No gate number is hard-coded. No agent can edit that file (static test: agents cannot import the settings loader writers, and the file is not writable by the agent process user).
- Every variant ever tried is counted in the experiment ledger, including failures, because the multiple-testing correction depends on it.

## T-050: Backtest engine (`lab/backtest.py`)
- Event-driven over closed 1M candles (3M and 5M from the shared resampler, T-013). Entry on the next bar's open, never the signal bar's close.
- Cost model from recorded Capital.com spreads per instrument and session (T-044/T-017). Until enough recorded data exists, use the configured conservative defaults and mark results `cost_model: provisional`.
- Walk-forward windows and rolling out-of-sample splits per the config. A `cost_stress_pct` option reruns with costs raised.
- Sizing uses the same `risk/sizing.py` functions as live trading (T-021), so backtest and live share one code path.
- Acceptance: a known-answer fixture strategy reproduces expected trades and P&L exactly; no look-ahead test (truncating future bars changes nothing before that time); cost stress works; deterministic given a seed; the holdout cannot be requested through this engine (test).

## T-051: StrategySpec and sandbox engine (`lab/spec.py`, `lab/engine.py`)
- `StrategySpec` (pydantic, strict): instrument, timeframe in {1m, 3m, 5m}, entry conditions (at most `max_conditions_per_strategy`), exit rules (stop, target, time stop, trailing), tunable parameters (at most `max_tunable_parameters`) with bounds, regime filters, session filters.
- Conditions use only the approved indicator library from T-040 by name and parameters. Unknown names, arbitrary expressions, imports and attribute access are rejected at parse time.
- The engine evaluates a spec against candle frames. It has no network, file or broker access.
- Acceptance: a corpus of invalid and malicious specs (unknown indicator, code strings, oversized, too many conditions, out-of-bound parameters) is rejected; valid specs round-trip to JSON; fuzz test with random JSON never raises anything but a validation error.

## T-052: Validator, ledger, promotion gate, decay monitor, allocator
- **Ledger** (Postgres table plus Parquet export): one row per experiment variant with spec hash, parameters, data range, results, and who proposed it. Append-only.
- **Validator:** applies Gate 1 exactly as in `strategy_lab.yaml` including the multiple-testing correction (use the ledger count; document the method, for example a Bonferroni or Benjamini-Hochberg style adjustment or deflated Sharpe, and justify the choice in the PR). Only module allowed to read the holdout; it reads it once per spec hash and records that it did.
- **Promotion gate:** moves stage and sets the capital cap from `stage_capital`. Gate 2 and Gate 3 read demo/micro-live trade results from the ledger of real fills. `LIVE_TRADING_ENABLED=false` means stages 3 and 4 are unreachable (test).
- **Decay monitor:** demotion rules from config; second demotion within 90 days retires the strategy.
- **Allocator:** splits risk budget across live strategies and enforces diversity (`min_strategy_diversity`) and the concurrent strategy cap.
- Acceptance: random-noise strategies (random entries, thousands of trials) are rejected at Gate 1 in repeated trials with a false-promotion rate near zero; a deliberately overfitted spec passes in-sample but is rejected by holdout or walk-forward; holdout files are unreadable by any other module (test with an import and path guard); every stage change writes `audit_log` and a Telegram alert.

## T-053: Pattern miner (`lab/miner.py`)
- Plain-code scans for opening-range behaviour, session effects, volatility compression/expansion, mean reversion after extension and event reactions. It emits candidate `StrategySpec` objects with the number of hypotheses tested.
- Each candidate goes through the same validator; every scan variant is added to the ledger so multiple-testing correction includes all of them.
- Acceptance: on pure noise data the miner's promoted count stays within the false-positive rate implied by the correction; a planted real pattern in synthetic data is found and survives the gates.

## T-054: Idea generator and post-mortem analyst
- LLM roles from `config/llm.yaml` (tiers per D-023). Outputs are `StrategySpec` JSON or a typed post-mortem report; invalid output is discarded and counted.
- Idea generator gets summaries and lessons, never the holdout and never raw gate numbers it could game beyond what the config documents.
- Acceptance: with MockLLM, the Lab runs end to end on paper: idea, spec, backtest, validator, ledger, stage change, alert. A mock LLM that tries to emit code, change gate values or request the holdout produces no effect.

## Exit checklist
Lab runs unattended for 24 hours on the pod with MockLLM and recorded data; ledger counts match runs; no holdout read outside the validator; owner-run drill confirms that raising a gate through chat is refused without TOTP.
